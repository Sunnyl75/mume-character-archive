THE FIELD GUIDE

A repeatable route to the Deck

  1. Add sources. Load research JSON/ZIP or prepare a webpage or one gameplay log. Adding sources saves pending evidence for review; it does not accept claims. Use the complete research ZIP to include retained originals.
  2. Review findings. Read original sources beside all attached claims. Accept, revise, reject or keep pending here. Add missing findings, attach attackers and locations to deaths, and map player links when needed. Use Find epoch response lines on an individual log to create pending wording observations.
  3. Whois (optional). Build the queue and copy its commands into Mudlet. Return to this same step, select the capture archive, preview new captures and import them. Player links remain preserved.
  4. Build & export. Rebuild the Deck and check the list of changed characters. Export accepted, independently dated response findings to a downloadable epoch comparison page and importable catalogue. Load the website’s current comparison catalogue first if it has separate edits.
  5. Publish. Explicitly publish the Deck update. For the epoch comparison, review the downloaded HTML, then upload its JSON in WordPress → Tools → MUME Dating Indicators. These are separate website updates.

What the source helper understands

It detects standard named death lines and player entries inside an explicit TROPHY display. It does not infer ownership, killers, uncertain dates or complex prose. Unrecognised text remains preserved. Split collections into individual logs and use the observer for that specific perspective.

Keep uncertainty visible

Different logs can describe the same death. Trophy snapshots show minimum counts before their display date and are never added into a lifetime total. Website friendship links do not establish common ownership.

Leave and return

The workbench remembers your current step, selected files and previous operations. Leave the launcher window open during an operation. Reopening the launcher resumes the workspace.
